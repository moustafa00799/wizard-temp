# دورة حياة الحملة المقيدة — CDKS

## الغرض

تضيف هذه المرحلة دورة حياة واضحة فوق `Canonical Blueprint` حتى ينتقل الناتج من المسودة إلى المراجعة ثم الاعتماد البشري، دون أن يتحول الاعتماد إلى إذن للنشر أو الإنفاق أو الكتابة إلى منصات الإعلانات.

> **Human Approval في هذه المرحلة يعني اعتماد Blueprint للمراجعة أو التحضير أو التصدير فقط. لا يعني إنشاء حملة خارجية، ولا تشغيلها، ولا إنفاق الميزانية.**

## الحالات والانتقالات

| الحالة | المعنى | الانتقالات المسموحة |
|---|---|---|
| `draft` | Blueprint محفوظ كمسودة قابلة للمراجعة | `draft → review` |
| `review` | يحتاج مراجعة بشرية | `review → approved` أو `review → rejected` |
| `approved` | تم اعتماده بشريًا للمراجعة/التحضير فقط | لا انتقال تنفيذي في هذه المرحلة |
| `rejected` | أُعيدت النتيجة للتعديل | `rejected → draft` |

الانتقال إلى `approved` يتطلب `actor_type=user` و`actor_user_id` غير فارغ. لا يستطيع `system` أو AI اعتماد الحملة. كما تُرفض الانتقالات غير القانونية، ومحاولات تغيير Canonical Blueprint hash، ومحاولات إعادة استخدام `event_id` بمحتوى مختلف.

## التخزين

أُضيفت migration مستقلة باسم `0006_campaign_lifecycle`. تحفظ `campaign_lifecycles` الحالة الحالية، وربطها بـ`workspace_id` و`blueprint_id` و`canonical_sha256`، وتحفظ `campaign_lifecycle_events` سجل الانتقالات بترتيب زمني.

تحتوي السجلات على قيود SQLite تمنع `generation_mode` من الخروج عن `blueprint_only`، وتمنع `external_actions_allowed` و`budget_spend_allowed` من أن تصبحا مفعّلتين. كل انتقال يُحفظ مع hash الـBlueprint حتى لا يمكن اعتماد نسخة غير النسخة المحفوظة.

## الربط مع توليد Blueprint

عند نجاح `/api/generate/v5`، يُحفظ الـCanonical Blueprint في runtime database ويُنشأ له lifecycle تلقائيًا في حالة `draft`. الحفظ قابل لإعادة التشغيل؛ فإذا أُعيد توليد النتيجة نفسها بنفس الـhash لا تُنشأ نسخة أو أحداث مكررة. أما اختلاف الـhash لنفس هوية Blueprint فيؤدي إلى فشل مغلق بدل استبدال النسخة السابقة.

مسار قاعدة البيانات الافتراضي للاختبار هو `.local/cdks-app.sqlite` ويمكن تغييره عبر `CDKS_APP_DB_PATH`. يجب استخدام مسار منفصل لكل بيئة عند الانتقال إلى staging أو production، مع عدم وضع قاعدة البيانات داخل Git.

## API

يوفر `GET /api/campaign-lifecycle` قراءة الحالة والأحداث، مع `workspace_id` و`lifecycle_id` أو `blueprint_id`. ويوفر `POST /api/campaign-lifecycle` عمليتي `create` و`transition` بعد التحقق من schema وhash والـworkspace binding.

واجهة `POST transition` لا تقبل اعتمادًا بلا مراجع بشري محدد، ولا تسمح بانتقال `approved → review` أو أي انتقال يؤدي إلى نشر أو إنفاق. تسجل المسارات أحداث audit آمنة في `audit_events` دون حفظ بيانات Wizard أو AI الخام.

## واجهة العميل

تظهر صفحة Blueprint لوحة **حالة الحملة والمراجعة البشرية**. يبدأ الناتج في `Draft`، ثم يمكن إرساله إلى `Review`، وبعدها يستطيع المراجع تسجيل `Human Approval` أو الرفض والإرجاع إلى المسودة. تعرض الواجهة صراحة أن الاعتماد لا يسمح بالنشر أو الإنفاق، وتعرض سجل الانتقالات عند الحاجة.

تظل أقسام Blueprint التفصيلية للقراءة والمراجعة، ولا توفر هذه المرحلة زرًا لإنشاء حملة على Meta أو Google Ads أو TikTok. كما لا تمنح AI أي دور في تغيير الحالة بدل الإنسان؛ دوره يظل استشاريًا.

## الاختبارات

يتحقق `campaign-lifecycle-regression.ts` من إنشاء lifecycle، وإعادة التشغيل الآمن، والانتقال إلى Review، ورفض اعتماد النظام، وقبول الاعتماد البشري، ورفض الانتقالات غير القانونية، ورفض hash غير الصحيح، وبقاء صلاحيات التنفيذ والإنفاق مقفلة.

ويتحقق `campaign-lifecycle-http-regression.ts` من دورة HTTP الكاملة بعد توليد Blueprint: `Draft → Review → Human Approval`. كما يتحقق من أن الاستجابة تحتفظ بالـhash الصحيح وأن النظام يرفض اعتمادًا صادرًا عن system.

تم تحديث Database Foundation وPersonal Staging ليتوافقا مع migration السادسة، وأضيفت اختبارات lifecycle إلى CI. لا تتصل الاختبارات بأي مزود خارجي ولا تستخدم بيانات عميل خامًا.

## ما لم تنفذه هذه المرحلة

لا تحتوي هذه المرحلة على صلاحيات كتابة للمنصات، ولا آلية نشر، ولا إنفاق، ولا دفع، ولا مزامنة خارجية. كما لا تعني حالة `approved` أن الحملة جاهزة للإطلاق؛ ما زالت بوابات التتبع والامتثال وقرارات CDKS والمراجعة التشغيلية قائمة.

المرحلة التالية، عند اعتمادها، هي بناء **Export/Preparation Layer** للـBlueprint المعتمد فقط، مع فحص نهائي للـreadiness، وإنشاء payload قابل للمراجعة قبل التفكير في أي Connector ذي صلاحية كتابة.
