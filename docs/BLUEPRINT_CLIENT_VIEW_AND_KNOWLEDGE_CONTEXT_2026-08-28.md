# تحسين عرض Blueprint وتجربة العميل

## نطاق الدفعة

تصلح هذه الدفعة مشاكل العرض المحصورة التي ظهرت في Blueprint، وتفصل بين بيانات القرار الحاكمة والتفاصيل التقنية. لم تتغير سلطة CDKS أو Canonical Blueprint، ولم تُضف أي صلاحية نشر أو إنفاق أو كتابة لدى مزودي الإعلانات.

## عرض القيم والحالات

أضيفت مكتبة عرض مشتركة في `src/lib/blueprint-display.ts`. تعرض الحالات بصياغة عربية مفهومة، وتحوّل القيم التي تبدأ بـ`unavailable:` إلى `غير متاح حاليًا` في البطاقة الرئيسية، مع الاحتفاظ بسبب مفصل قابل للعرض داخل بطاقة الأدلة. كما تحوّل معرفات قواعد مثل `RF-019` إلى `قواعد CDKS` بدل عرض معرف داخلي للعميل.

تتضمن المكتبة guard دفاعيًا يمنع عرض نصوص JavaScript أو تفاصيل framework مثل `function StatusPill(...)` و`jsxDEV` و`TURBOPACK` و`node_modules/next` حتى لو وصلت قيمة غير صالحة إلى renderer. وأضيف اختبار regression يثبت ذلك.

## Knowledge Context

أزيل اختيار العميل للسياق من Step12. لا يرسل Wizard بعد الآن `knowledge_context_id` أو `knowledge_strategy_selection` إلى generate v5. يحدد الخادم سياقًا مسموحًا تلقائيًا من المدخل canonical فقط عندما تتطابق إشارات السوق والنشاط مع نطاق الأدلة المنقحة. السياق غير المطابق لا يتم تفعيله، وأي معرف يرسله العميل يتم تجاهله.

المطابقة الحالية محافظة ومحدودة بسياق ShaadDesign: يجب أن تظهر إشارات السعودية في المواقع المستهدفة وإشارات التصميم الداخلي/الديكور في بيانات النشاط. لا تكفي عبارة عامة مثل نشاط في السعودية لتفعيل السياق. يظل السياق restricted advisory context، ولا يثبت Market Validation العام أو أداء السوق، وتظل المقاييس غير المثبتة `unavailable`.

تعرض صفحة Blueprint السياق الذي استخدمه الخادم كـprovenance read-only، ولا تمنح العميل سلطة اختيار أو تغيير مصدر المعرفة.

## تنظيم Blueprint

احتفظت الدفعة بجميع renderers والأقسام الأصلية وعددها 26 لضمان parity، وأضافت طبقة عرض بستة محاور:

1. ملخص القرار: الملخص، الاستراتيجية، المسار التسويقي، هيكل الحملات والجمهور.
2. خطة التنفيذ: تحليل الجمهور، الاستراتيجية الإبداعية، الزوايا، واستراتيجية العرض.
3. الميزانية والقياس: توزيع الميزانية، التتبع، المراقبة، الإدارة، الاختبارات، والمؤشرات المرجعية.
4. السوق والمنصات: سياق السوق وإرشادات المنصات.
5. الجاهزية والمخاطر: خطة الإطلاق، أول 14 يومًا، الإصلاحات، الامتثال، المخاطر، وحالة النظام.
6. التفاصيل التقنية: التدقيق التقني والتشخيص والتتبع للمراجع أو المطور.

يختار المستخدم المحور أولًا، ثم يرى أقسام ذلك المحور فقط. هذا يقلل التشتيت دون حذف البيانات أو تغيير عقد Blueprint.

## حدود البيانات

القيم السوقية مثل CPC وCPA وCVR وCTR وROAS وتشبع السوق والإنفاق التنافسي لا تُخمن. عند غياب evidence مطابق تظهر كغير متاحة مع سبب مفهوم. Planned events وMeasurement Plan ليست Observed Performance، ولا يتم تفسيرها كتقرير نتائج.

## الاختبارات المطلوبة

يجب أن ينجح regression العرض، Knowledge Context regression، Golden v5 HTTP، Lifecycle، Measurement، Workspace Isolation، Security، Local Auth، Personal Staging، TypeScript، Production Build، وCI. فشل الاتصال في اختبارات HTTP المحلية لا يُعد فشلًا منطقيًا إذا لم يكن الخادم مشغّلًا؛ لذلك تُعاد اختبارات HTTP على خادم production محلي.

## خارج نطاق هذه الدفعة

إعادة تسمية كامل المصطلحات تجاريًا وصناعيًا، دعم العربية والإنجليزية على مستوى المنتج، وتوسيع AI أو تعميق AI Reasoning مؤجلة إلى دراسة مستقلة بعد إغلاق هذه الدفعة. كما لا يعني Human Approval إطلاقًا أو نشرًا أو إنفاقًا.
